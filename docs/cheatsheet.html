CyberVM-AI cheatsheet · 1/2 · Working with a VM

Run on the Ubuntu host unless marked. <name> is the short name you gave new.

host commandkali$ = inside the VM

  1. cybervm new web01
  2. cybervm start web01
  3. cybervm snapshot web01 before-exploit
  4. cybervm stop web01

B · Need internet or a cloud agent
  1. cybervm stop web01

1 · Create a VM

cybervm new <name> [--profile P | --ram GB [--cpus N]]
(no flags)Linked clone of golden at balanced size, network offline, snapshot clean taken for you.
--profile lean8 GB / 4 vCPU. Smallest — when you want several VMs up together.
--profile balanced12 GB / 6 vCPU. The default — one VM comfortably.
--profile large16 GB / 8 vCPU. Burp + browser + heavy scans; one VM at a time.
--ram 10Exact RAM. 10 or 10G = GB, 10240M = MB. Min 2 GB, max host RAM.
--cpus 5Exact vCPUs. Left out → RAM in GB ÷ 2. Max = host threads.

Rules: --profile cannot be mixed with --ram/--cpus. There is no --net on new — set the network at start. Examples: cybervm new web01 --profile lean · cybervm new big --ram 16 --cpus 8

2 · Network mode — the main switch (pick one per session; VM must be off to change it)

ModeInternetHost AI + RAGtransferUse it forWatch out
offlinenoyesyesEveryday lab work with the local model and RAG. Default for every new clone.No apt/pip, no cloud models, no mcp update.
airgapnononoRunning something untrusted, or proving nothing can leave the VM.cybervm ai, RAG and transfer stop working.
natyesyesyesCloud agents (claude, codex), apt/pip installs, cybervm mcp update, internet targets.VM has outbound internet. Host loopback stays blocked.
bridgedyesyesyesVM needs its own address on your LAN: listeners, reverse shells, LAN discovery.Sits on your real network — breaks the sandbox. Asks you to type yes.
cybervm net <name> <mode>Set the mode and stop there. VM off. The mode is stored and reused until you change it.
cybervm start <name> --net <mode>Set the mode and boot in one step. The usual way.
cybervm start <name>Boot with the stored mode. A new clone's stored mode is offline.
curl -m5 https://kali.orgCheck from inside: answers only in nat / bridged. curl -s $OLLAMA_HOST/api/tags answers in every mode except airgap.

3 · Start, stop, list

cybervm start <name> [--net MODE] [--headless]
--net MODEoffline | airgap | nat | bridged — see block 2.
--headlessNo VM window. Use for transfer/SSH-only work. Leave it out when you need the desktop, Burp or the Playwright browser.
cybervm stop <name>Clean ACPI shutdown.
cybervm listEvery VM with state, RAM and vCPU.

“Not enough host RAM”: start keeps CYBERVM_HOST_RESERVE_MB (6144) free for the host. Stop another VM or resize this one smaller.

4 · Resize (VM off)

cybervm resize <name> [--ram GB] [--cpus N]
--ram 16New RAM; vCPU follows (÷ 2 → 8) unless you also pass --cpus.
--cpus 4vCPU only; RAM stays as it is.

At least one flag is required. --profile is not accepted here. Disk size never changes. Base and Golden are refused.

5 · Cloud API keys (VM running; nat to use them)

cybervm secrets push <name> [names…]
[names…]anthropic openai deepseek openrouter. None given = all four. Goes to VM memory (tmpfs) only.
source /run/user/1000/cybervm/secrets.envLoad the keys into this shell.
cybervm secrets wipe <name>Shred them when done.

6 · Snapshots and delete

cybervm snapshot <name> <tag>Save a point to return to. Works while running. Do it before a risky step.
cybervm restore <name> <tag>VM off. Back to that point; everything after it is lost.
cybervm restore <name> cleanclean is the snapshot new took — a fresh clone again.
cybervm destroy <name>Deletes the clone and its disks after you type yes. Golden is untouched; Base/Golden are refused.

7 · Files in and out (VM running, not airgap)

cybervm transfer in <name> <file> [guest/dir]
[guest/dir]Where it lands in the VM. Default /mnt. File is written as root, world-readable.
cybervm transfer out <name> <guest/file> [host/dest]
[host/dest]Host folder or file name. Default: the directory you are in. Overwrites a file of the same name.
echo hi | sudo tee /mnt/a.txt/mnt is root-only: write there with sudo.

8 · Inside the VM — local AI (works offline)

source /etc/profile.d/cybervm.shSets $OLLAMA_HOST, $CYBERVM_RAG_URL.
cybervm ai run "<prompt>"Answer from the host model.
cybervm ai run <model:tag> "…"Other model, this call.
export CYBERVM_AI_MODEL=<model:tag>New default model.
cybervm ai listModels available on the host.
cybervm ai pull <model>Download a model onto the host.
cybervm ai rm <model>Delete a model from the host.
cybervm ai opencode [model:tag] "<task>"Agent run on the local model.
cybervm opencode "<task>"Shortcut for the row above.
opencode · claude · codexCloud models: nat + keys (5).

9 · Inside the VM — MCP browser and RAG

cybervm mcp statusMCP + Chromium versions.
cybervm mcp verifyOffline health check of the browser.
cybervm mcp updateGet latest. Needs nat|bridged.
curl -s $CYBERVM_RAG_URL/search -d '{"query":"sqli"}' | jq .Ask the RAG. Filters: page 2, block 12.
  • Never work in Base or Golden — only in clones.
  • net, resize and restore need the VM off; transfer and secrets need it running.
  • After a host reboot, start/ai/rag bring the AI plane and Ollama back by themselves.

11 · Host AI (Ollama)

cybervm ai listModels installed.
cybervm ai pull [model]One model, or all of models.yml with no argument.
cybervm ai rm <model>Delete a model.
cybervm ai run [model:tag] "…"Quick answer on the host.
cybervm ai bench [model]Speed test → docs/benchmarks/.
cybervm ai tune [flags]Cap Ollama so a running VM stays responsive.
 --cpu-quota 500Max CPU, % of one core. 500 ≈ 5 cores. Lower = VM smoother, AI slower.
 --nice 10Priority. Higher = Ollama yields more to the VM.
 --keepalive 2mUnload an idle model after this long. Frees ~2 GB RAM.
 --context 4096Context length. Smaller = less RAM, faster; untuned is 8192.
 --governorCPU governor → performance. Faster, more heat.
 --swappiness 10Lower swappiness. Use if the host starts swapping.
cybervm ai untuneRemove the cap and restore everything.

12 · RAG knowledge base (host docker)

cybervm rag up | down | statusStart, stop, show per-collection counts.
cybervm rag update liveFast-moving intel. Run daily. Needs internet.
cybervm rag update stableReference material. Run weekly.
cybervm rag update personalYour own notes.
cybervm rag updateAll three layers.
 --only <source-id>Re-ingest one source, e.g. after a rate-limit failure.
cybervm rag backupCopy the vector DB to rag/backups/.
cybervm rag restore <path>Put a backup back.

Source ids — live: nvd_cve, cisa_kev, github_advisories, epss, nuclei_templates. stable: mitre_attack, cwe, owasp_wstg, owasp_cheatsheets, payloadsallthethings. personal: personal_notes.

Search filters (JSON body of /search): query (required) · tier_max 1–4, 1 = authoritative only, default 4 · since "2026-09-01" · cve "CVE-…" · kind · limit default 8.

13 · Golden image

cybervm golden buildRe-provision from config/ and snapshot.
cybervm golden verifyCheck-mode + smoke tests.
cybervm golden resetDelete golden and its snapshot chain, rebuild from base. Reclaims disk.
 --dry-runShow the plan, change nothing.
 --keep-ovaExport an .ova first as a safety copy.
 --no-verifySkip the tests. Result is untested.
cybervm pins check | refreshBurp pins vs live store; re-pin if drifted.
cybervm host ollama-pinRefresh the pinned Ollama release.
cybervm doctorPASS/FAIL readiness table.

14 · Release, move, back up

cybervm releaseGolden → .ova + sha256 + manifest.
cybervm release listExported releases.
cybervm release rm <name.ova>Delete one.
cybervm release prune [n]Keep the newest n. Default 2.
cybervm import <file.ova>Register a release on this machine.
cybervm backup <dest>Source + releases + RAG backups.

15 · First-time setup (once, in order)

cp .cybervm.env.example .cybervm.envThen set CYBERVM_ROOT.
./cybervm host-setupDeps, network, Ollama, ufw, PATH.
cybervm doctorMust be all PASS.
cybervm pins checkpins refresh if it reports drift.
cybervm base importRegister the Kali image.
cybervm golden buildProvision + snapshot.
cybervm rag upThen rag update.

16 · When something breaks

clone brokenrestore <name> clean, or destroy + new
golden brokengolden reset — base is never touched
AI not answeringdoctor, then ai list (revives the AI plane + Ollama)
no internet in VMmode is offline: stop → start --net nat
transfer failsVM not running, or mode is airgap
new machinehost-setup → import <ova> → rag up
all commandscybervm help (host and VM)
  • Add a tool by editing config/ then golden build — never hand-edit a VM you want to keep.
  • API keys stay on the host in ~/.config/cybervm/secrets.env and never enter an image.
  • CYBERVM_HOST_IP is a VirtualBox host-only adapter address, not your LAN IP.
