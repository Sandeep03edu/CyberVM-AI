CyberVM-AI cheatsheet

Run on the Ubuntu host unless marked. First run is ./cybervm host-setup; after that cybervm works from any directory.

host command kali$ = inside the VM

1 · First-time setup (once per machine, in this order)

cp .cybervm.env.example .cybervm.envset CYBERVM_ROOT
./cybervm host-setupdeps, AI-plane net, Ollama, ufw, PATH
cybervm doctorreadiness table — must be all PASS
cybervm pins checkBurp extension pins vs live store
cybervm pins refreshonly if check reports DRIFT
cybervm base importregister verified Kali image
cybervm golden buildAnsible-provision + snapshot
cybervm golden verifycheck-mode + SSH smoke tests
Daily loop
  1. cybervm new work-01
  2. cybervm start work-01 --net offline
  3. …work in the VM…
  4. cybervm stop work-01
  5. cybervm destroy work-01

2 · VM lifecycle

cybervm new <name>linked clone, 12GB/6, offline, snapshot “clean”
cybervm new <name> --profile lean|balanced|large8 · 12 · 16 GB
cybervm new <name> --ram 10 [--cpus 5]exact; cpus default GB÷2
cybervm resize <name> [--ram GB] [--cpus N]VM off
cybervm start <name> [--net MODE] [--headless]MODE: see 3
cybervm stop <name>ACPI shutdown
cybervm listVMs, state, RAM, vCPU
cybervm snapshot <name> <tag>save a point to return to
cybervm restore <name> <tag>VM off
cybervm restore <name> cleanback to the fresh clone
cybervm destroy <name>deletes clone + disks (type yes)

3 · Network mode (VM must be off)

cybervm net <name> offline|airgap|nat|bridgedor use start --net
offlinedefault. No internet. Host Ollama + RAG reachable.
airgapNo network at all — no AI, no RAG, no transfer.
natInternet + AI plane. Needed for cloud agents, apt, mcp update.
bridgedVM sits on your real LAN. Breaks the sandbox; asks for yes.

4 · File transfer (VM running)

cybervm transfer in <vm> <file> [guest/dir]host → VM, default /mnt
cybervm transfer out <vm> <guest/file> [host/dest]VM → host, default cwd
echo hi | sudo tee /mnt/a.txt/mnt is root-only: write with sudo

5 · Cloud API keys (VM running, net nat)

cybervm secrets push <vm> [names…]anthropic openai deepseek openrouter
source /run/user/1000/cybervm/secrets.envload keys
cybervm secrets wipe <vm>shred them

6 · Local AI on the host (Ollama)

cybervm ai listmodels installed
cybervm ai pull [model]no arg = all of config/ai/models.yml
cybervm ai rm <model>delete a model
cybervm ai run "<prompt>"default qwen2.5:3b-instruct
cybervm ai run <model:tag> "<prompt>"pick the model
cybervm ai bench [model]tokens/s → docs/benchmarks/
cybervm ai tunecap Ollama so a VM stays responsive
flags: --cpu-quota 400 --nice 10 --keepalive 5m --context 2048 --governor --swappiness 10
cybervm ai untuneremove the cap, restore defaults

7 · Inside the VM (guest cybervm CLI — works offline)

source /etc/profile.d/cybervm.shexports the AI-plane vars

cybervm ai run <model:tag> "<prompt>"pick the model
cybervm ai listmodels on the host
cybervm ai pull <model>pull onto the host
cybervm ai rm <model>delete from the host
cybervm ai opencode [model:tag] "<task>"agent, local model
cybervm opencode "<task>"shortcut for the line above
opencode · claude · codexcloud models need nat + keys

11 · Golden image upkeep

cybervm golden buildre-provision after editing config/
cybervm golden verifyconfirm it is sound
cybervm golden resetwipe golden, rebuild from base
flags: --dry-runshow the plan only
flags: --keep-ovaexport an .ova first
flags: --no-verifyskip the tests
cybervm host ollama-pinrefresh pinned Ollama release
cybervm host-setupsafe to re-run; needed if the repo moves

12 · Release, move, back up

cybervm releasegolden → .ova + sha256 + manifest
cybervm release listexported releases
cybervm release rm <name.ova>delete one
cybervm release prune [keep-n]keep newest n (default 2)
cybervm import <file.ova>register a release on this machine
cybervm backup <dest>source + releases + RAG snapshot

13 · When something breaks

clone brokencybervm restore <name> clean, or destroy then new
golden brokencybervm golden reset (base is never touched)
AI not answeringcybervm doctor, then cybervm ai list (re-applies the AI-plane address and restarts Ollama)
VM won't start“Not enough host RAM” → stop another VM or resize smaller
new machinehost-setup → import <ova> (or base import + golden build) → rag up → rag update live
all commandscybervm help on the host · cybervm help in the VM
  • Never work in Base or Golden. Work only in clones; destroy refuses the other two.
  • net, resize and restore need the VM powered off. snapshot does not.
  • A new clone is always offline. start without --net reuses the last mode you set.
  • Playwright MCP is headed-only: start the clone with a GUI (no --headless) to see the browser.
  • Add a tool by editing config/ then golden build — never hand-edit a VM you want to keep.
  • API keys live in ~/.config/cybervm/secrets.env on the host and never enter an image.
  • The AI-plane address is CYBERVM_HOST_IP in .cybervm.env (a VirtualBox host-only adapter, not your LAN IP).
  • After a host reboot the adapter is down until start, ai or rag brings it back; that is normal.
  • VM names: use the short name you gave new (work-01) in every command.
